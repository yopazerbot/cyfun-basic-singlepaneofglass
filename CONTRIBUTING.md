# Contributing

Scope stays narrow: CyFun 2025 assessment (BASIC, IMPORTANT, ESSENTIAL), evidence, connectors and verification support. Features outside that (other frameworks, multi-tenant, notifications) belong in a fork.

## Development

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
ruff check . && ruff format --check .
pytest -q
```

Run the application locally (local account admin / admin, forced password change at first login):

```bash
cp .env.example .env     # set APP_BASE_URL=http://localhost:8000
PYTHONPATH=app uvicorn cyfun.main:app --reload     # Windows: scripts/run-dev.ps1
```

## Rules

* Scoring and risk logic must keep reproducing the CCB workbook results for all three levels; the tests in `tests/test_scoring.py`, `tests/test_levels.py`, `tests/test_risk.py` and `tests/test_export.py` are the contract.
* Framework JSON is generated by `scripts/`, never edited by hand. Guidance text lives in `guidance_basic_2025.json` and is written in plain language.
* No new runtime dependency without a reason stated in the pull request.
* No inline scripts or styles in templates (strict CSP). No external assets.
* Every write endpoint uses `require_admin` and logs an activity row.
* Connector evaluation logic goes in pure `evaluate_*` functions with unit tests.
* Keep the CCB workbooks out of the repository.

## Pull requests

One topic per pull request, tests included, CI green. Describe what changed and why in plain sentences.
